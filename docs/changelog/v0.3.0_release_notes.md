# CrystallographicFFT.jl v0.3.0

## Highlights

🖥️ **GPU acceleration** — CUDA support via a zero-cost weak-dependency extension. Both General and Centered CFFT paths run on NVIDIA GPUs out of the box.

⚡ **Device-agnostic architecture** — The entire compute pipeline has been rewritten on top of KernelAbstractions.jl. A single codebase now targets CPU and GPU with no user-facing API changes.

📐 **R2C FFT transforms** — New `rcfft!` / `ircfft!` functions exploit real-valued symmetry for additional memory and compute savings. All 230 space groups are supported.

🌟 **Star mapping API** — `SubgridStarMap` provides efficient bidirectional conversion between subgrid points and their symmetry orbits (stars), enabling orbit-averaged field representations.

---

## What's New

### Features

- **Device-agnostic compute pipeline** built on KernelAbstractions.jl with new core modules: `types.jl`, `kernels.jl`, `planning.jl`, `execute.jl`.
- **CUDA GPU support** as a weak extension (`ext/CUDAExt.jl`) — automatically activates when CUDA.jl is loaded. Includes batched CuFFT and optimized kernel dispatch.
- **`rcfft!` / `ircfft!`** — Real-to-complex Crystallographic FFT using `rfft`/`irfft`. New plan types: `RCFFTPlan`, `IRCFFTPlan`, `GeneralRCFFTPairPlan`.
- **`SubgridStarMap`** — Union-Find-based star construction with `build_subgrid_star_map`, `expand_stars!`, `compress_stars!`.
- **`cfft_kk_orbsum`** — Orbit-weighted **k**⊗**k** sums over the spectral ASU for stress tensor computation.

### Performance

| Function | Space group | Speedup | Before → After |
|---|---|---|---|
| `build_subgrid_star_map` | Ia-3d, N=128 | **31×** | 22 s / 8.4 GB → 0.7 s / 4.7 MB |
| `plan_rcfft_pair` | Ia-3d, N=64 | **6×** | 5.5 s → 0.9 s |
| `calc_spectral_asu` | all groups | — | Zero-allocation inner loop via NTuple |
| `recommended_N` | Ia-3d, etc. | — | Dynamic `auto_L`-based divisor; correct for all 230 groups |

### Bug Fixes

- Fixed a minor bug in alive mask computation.

---

## Breaking Changes

- Legacy internal modules (`KRFFT`, `QFusedKRFFT`, `DiffusionSolver`) have been archived to `src/archived/`. The public API (`plan_cfft`, `cfft!`, `icfft!`, etc.) remains unchanged.
- Plan struct types are now fully parametric (e.g., `ForwardPlan{T,D,P,VA,AA,VI}`) — this only affects code that explicitly referenced internal plan types.

## New Dependencies

|---|---|---|
| `Adapt.jl` | v4 | hard |
| `CUDA.jl` | v5 | weak (optional) |

## Quick Start: GPU

```julia
using CUDA, CrystallographicFFT

N = (64, 64, 64)
pair = plan_cfft_pair(N, 225, 3; array_type=CuArray{Float64})
f  = CUDA.rand(Float64, pair.fwd.M...)
F̂  = CuVector{ComplexF64}(undef, pair.n_spec)

cfft!(F̂, pair, f)    # forward on GPU
icfft!(f, pair, F̂)   # inverse on GPU
```

## Quick Start: rcfft

```julia
using CrystallographicFFT

N = (64, 64, 64)
pair = plan_rcfft_pair(N, 221, 3)
f  = rand(Float64, pair.fwd.M...)
F̂  = Vector{ComplexF64}(undef, pair.n_spec)

rcfft!(F̂, pair, f)    # real-valued forward
ircfft!(f, pair, F̂)   # real-valued inverse
```
